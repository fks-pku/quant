# Parquet Lake Storage

This project treats the OSS-backed Parquet lake as the cross-machine source of truth.
DuckDB is the local query engine/cache layer: read paths register Parquet files as DuckDB views, and only legacy tools should require materialized `.duckdb` sidecars.

The local lake lives at:

```text
quant/infrastructure/var/parquet_lake/
```

The default remote is:

```text
oss:quant-duckdb-backup/vk-quant/parquet-lake
```

## Native Daily Update

For routine daily updates, write directly into the local Parquet lake and sync only touched partitions to OSS:

```bash
python quant/scripts/update_cn_live_data.py \
  --storage-backend parquet-lake \
  --end 2026-06-01 \
  --sync-parquet-lake
```

This path writes these datasets directly through `ParquetLakeStorage`:

```text
stock_ohlcv
etf_ohlcv
index_ohlcv
fund_nav
corporate_actions_dividends
```

The same storage writer is generic and can write all lake datasets through `write_frame()`. During the transition, `daily_basic`, `financial_indicators`, `security_status`, and `index_weight` are still generated by their existing DuckDB sidecar scripts, then immediately merged into matching Parquet partitions when `--storage-backend parquet-lake` is used. Treat those sidecar files as generator caches, not the cross-machine source of truth.

Use `--sync-dry-run` to inspect the exact `rclone sync` commands without uploading.

Configure that `oss` rclone remote once per machine before publishing or pulling:

```bash
rclone config create oss s3 provider Alibaba \
  access_key_id <ALIYUN_ACCESS_KEY_ID> \
  secret_access_key <ALIYUN_ACCESS_KEY_SECRET> \
  endpoint <OSS_ENDPOINT>
```

`snapshot --check-only` verifies that the `oss` remote exists before it reports success.

The publisher exports date-bearing datasets as Hive-style partitions:

```text
stock_ohlcv/year=2026/month=05/day=29/data.parquet
daily_basic/year=2026/month=05/day=29/data.parquet
security_status/year=2026/month=05/day=29/data.parquet
```

## Legacy DuckDB Snapshot

If you already have DuckDB sidecars and want a full migration/snapshot, publish those sidecars as day-partitioned Parquet to Alibaba OSS with:

```bash
python -m quant.scripts.publish_parquet_lake snapshot --mode full
```

Run the snapshot publisher only after live data ingestion has finished. It opens the DuckDB files read-only, but full export still scans large files and should not compete with ingestion jobs.

## First Full Publish

```bash
python -m quant.scripts.publish_parquet_lake snapshot --mode full --keep-stage
```

`--keep-stage` keeps the temporary local Parquet directory for inspection. Remove it after checking if disk space matters.

## Legacy Daily Publish

After a daily update, publish only the affected day partition:

```bash
python -m quant.scripts.publish_parquet_lake snapshot --date 2026-06-01
```

The snapshot command exports only matching rows into a temporary local lake, then `rclone sync`s the exported `year=/month=/day=` directories to OSS. Re-running the same day overwrites that day partition only.

To backfill a date range, use:

```bash
python -m quant.scripts.publish_parquet_lake snapshot --start 2026-05-20 --end 2026-05-31
```

Use `--check-only` before installing a scheduled task to verify the DuckDB sidecars and `rclone` are available:

```bash
python -m quant.scripts.publish_parquet_lake snapshot --date 2026-06-01 --check-only
```

## Pull A Local Mirror

On another machine:

```bash
python -m quant.scripts.publish_parquet_lake pull
```

This mirrors OSS into `quant/infrastructure/var/parquet_lake/`.

## Query Through DuckDB Views

After pulling a local mirror, default read-only storage automatically uses the local lake:

```python
from quant.infrastructure.data.storage_duckdb import DuckDBStorage

storage = DuckDBStorage(read_only=True)
bars = storage.get_bars_for_symbols(["600519"], start, end, "1d")
```

`DuckDBProvider` uses the same storage path, so backtests and API read paths do not need to restore `.duckdb` sidecars when `quant/infrastructure/var/parquet_lake/_manifest.json` exists.
The storage registers local views such as:

```text
daily_cn_ochl
daily_basic.cn_daily_basic
security_status.cn_security_status_daily
cn_etf.daily_cn_ochl
cn_index.daily_cn_ochl
corp_actions.cn_dividends
fund_meta.cn_fund_instruments
fund_nav.cn_fund_nav
```

To force legacy sidecars for a specific read path:

```python
storage = DuckDBStorage(read_only=True, prefer_parquet_lake=False)
```

To force a custom lake path:

```python
storage = DuckDBStorage(
    read_only=True,
    parquet_lake_root="/path/to/parquet_lake",
    prefer_parquet_lake=True,
)
```

## Restore DuckDB Sidecars

Rebuild local DuckDB files from the pulled Parquet lake only when a legacy tool requires materialized `.duckdb` sidecars:

```bash
python -m quant.scripts.publish_parquet_lake restore --force
```

This writes sidecars under `quant/infrastructure/var/duckdb/live/`.

## Ad Hoc Query With DuckDB

After pulling a local mirror, raw SQL can still read a dataset directly:

```sql
SELECT *
FROM read_parquet(
  'quant/infrastructure/var/parquet_lake/stock_ohlcv/year=*/month=*/day=*/*.parquet',
  hive_partitioning = false
)
WHERE symbol = '600519';
```

For direct OSS reads, configure DuckDB `httpfs` with the Alibaba OSS S3-compatible endpoint and read the same `s3://` bucket prefix.
